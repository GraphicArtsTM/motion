# Ключ API таксопарка (Яндекс Fleet): какие доступы дать

Ключ создаётся в кабинете парка: **fleet.yandex.ru → Настройки → API (ключи API) → Создать ключ**.
Создайте **отдельный ключ только для бота** — его можно отозвать, не трогая другие интеграции.
Мастер настройки (`setup.bat`, шаг 3) проверяет каждый доступ кнопкой «Проверить доступы ключа» и показывает ✅/❌.

Из кабинета понадобятся три значения: **Client ID** (вида `taxi/park/…`), **API-ключ** и **ID парка**.

## Обязательные доступы

| Метод (как в кабинете и документации Fleet) | Тип | Зачем боту |
|---|---|---|
| Получение списка профилей исполнителей | чтение | Автопроверка друга по базе парка: есть ли он уже в парке, когда создан профиль, не уволен ли недавно |
| Получение профиля исполнителя | чтение | Номер водительского удостоверения, если его нет в списке профилей |
| Получение списка заказов | чтение | Баллы друзей: тариф, стоимость, дистанция и длительность заказов |
| Получение списка категорий транзакций | чтение | Выбор категории, под которой выплаты видны в кабинете и в Яндекс Про |
| **Создание транзакции на балансе исполнителя** | **запись** | Вывод денег водителю на баланс Яндекс Про. Только новый метод, **не** «[Устаревший] Создание транзакции…» |
| Получение информации о статусе транзакции | чтение | Сверка выплаты при обрыве связи — защита от двойной выплаты |
| Получение списка транзакций по исполнителю | чтение | Резервная сверка выплаты по метке `REFBOT-W…` в описании |

Без доступа «Создание транзакции» бот работает, но вывод денег идёт только через менеджера (кнопка
«Выплачено вручную» в админ-чате) — мастер сам включит этот режим.

## Желательные доступы

| Метод | Тип | Зачем |
|---|---|---|
| Получение списка автомобилей · Получение автомобиля | чтение | Тариф по категории авто, если его нет в заказе (важно для грузовых) |
| Получение времени исполнителя на линии | чтение | Антифрод: баллы без времени на линии, «невозможные» баллы в час |
| Получение списка условий работы | чтение | Сегментация рассылок (аренда / свой автомобиль) |
| Получение заблокированного баланса водителя | чтение | Карточка водителя в админке |

## Не давайте эти доступы — они боту не нужны

* создание и редактирование профилей исполнителей, создание и редактирование автомобилей;
* привязка и отвязка автомобиля, гараж;
* курьеры Еды, автокурьеры, пешие курьеры, баланс Заправок;
* транзакции парка, транзакции по заказам, трек заказа;
* любые методы с пометкой «[Устаревший]» или «[deprecated]».

Принцип минимальных прав: если ключ утечёт, им нельзя будет изменить данные водителей или автомобилей —
только читать и создавать транзакции.

## Безопасность ключа

* Ключ хранится только в файле `.env` на компьютере/сервере бота. Не пересылайте его в мессенджерах и не
  выкладывайте `.env` в git (файл уже в `.gitignore`).
* Если в кабинете можно ограничить ключ по IP — укажите IP сервера бота.
* При увольнении сотрудника, у которого был доступ к `.env`, перевыпустите ключ и введите новый через `setup.bat`
  (поле можно оставить пустым — тогда сохранится старый).

## Как работает проверка в мастере

Проверка ничего не меняет в парке:

* методы чтения вызываются с ограничением в 1 запись;
* методы с параметром — с несуществующим ID: ответ 400/404 значит «доступ есть, объект не найден»;
* «Создание транзакции» проверяется заведомо неверным запросом (сумма 0 несуществующему водителю) — деньги не
  двигаются.

Расшифровка: **401** — неверный ключ или Client ID (или ключ от другого парка); **403** — у ключа нет доступа к
методу, отметьте его в кабинете. Мастер также показывает, есть ли в заказах **тариф** и в профилях **номер ВУ** —
это главные пункты «Шага 0» (`API_SCHEMA.md`). Полная разведка с сохранением ответов — `scripts/api_recon.py`.

> Названия методов в кабинете могут незначительно отличаться от таблицы; ориентируйтесь на смысл и на результат
> проверки в мастере.
